# Spec Delta

## Purpose

提供公众号历史文章列表、文章详情与互动指标历史能力，以时间快照方式保留每次采集的阅读量、点赞量、在看数等指标，使后续可以计算观测变化而不丢失历史数据。

## ADDED Requirements

### Requirement: 历史文章列表

系统 MUST 支持按公众号获取分页历史文章列表，返回标题、文章链接、发布时间及最近一次保存的互动指标；列表 MUST 使用平台最近一次保存的指标，MUST NOT 在用户查看时自动实时调用第三方接口。

#### Scenario: 查询文章列表
- **WHEN** 用户请求某公众号的历史文章
- **THEN** 系统返回分页文章及各自最近一次保存的指标

#### Scenario: 文章缺失发布时间
- **WHEN** 某文章数据源未提供发布时间
- **THEN** 该文章 `published_at` 为 `null`，且不参与需要发布时间排序的运算

### Requirement: 文章详情与指标历史

系统 MUST 提供按内部 ID 查询文章详情的能力，并 MUST 支持查询该文章按时间排序的指标历史快照；每个快照 MUST 记录 `observed_at`（平台采集时间），并在供应商提供时记录 `raw_updated_at`。

#### Scenario: 查询指标历史
- **WHEN** 一篇文章存在多次指标采集
- **THEN** 系统按时间返回多个快照，而不是只返回一个当前值

#### Scenario: 只有一次观测
- **WHEN** 一篇文章仅有一次指标快照
- **THEN** 系统返回该单点数据，且不生成虚构的历史曲线

### Requirement: 指标快照不可覆盖

每次采集文章指标 MUST 追加新的快照记录，MUST NOT 覆盖既有快照；系统 MUST 区分文章发布时间与指标采集时间。

#### Scenario: 重复采集同篇文章
- **WHEN** Worker 对同一文章在不同时间采集两次指标
- **THEN** 数据库存在两条独立快照，各自带有自己的 `observed_at`

#### Scenario: 指标缺失
- **WHEN** 某次采集供应商只返回阅读量
- **THEN** 该快照的点赞量、在看数等未返回字段为 `null`

### Requirement: 观测阅读量变化

当同一文章存在至少两次有效观测时，系统 MUST 能计算观测阅读量变化；当上次阅读量为 0 或缺失时 MUST NOT 计算变化率；对外表述 MUST 使用「观测阅读量变化」，MUST NOT 声称等于真实新增阅读人数。

#### Scenario: 两次有效观测
- **WHEN** 文章存在两次有效阅读量快照
- **THEN** 系统给出当前值减上次值的观测变化

#### Scenario: 上次阅读量为零
- **WHEN** 上次快照阅读量为 0 或缺失
- **THEN** 系统不计算变化率并返回不可用标记
