# Spec Delta

## ADDED Requirements

### Requirement: 首次信息录入表单

首次登录且尚未提交登记的用户 MUST 在进入主应用前被引导填写信息登记表单，且该表单仅需填写一次。表单 MUST 包含以下字段：获知途径（单选，必填：百度等搜索引擎/公众号文章/朋友推荐/媒体平台或网站/其他）、用户类型（单选，必填：广告主/品牌方/广告媒介机构/舆情机构/号主/4A公司/其他）、公司名字（必填）、证明材料（必填，见上传要求）、姓名（必填）、联系电话（必填）；「需求」为可选文本。选择「其他」的项 MUST 允许并记录自定义文本。

#### Scenario: 首次登录被引导登记
- **WHEN** 用户首次登录且尚未提交登记
- **THEN** 进入主应用前被引导到信息录入表单

#### Scenario: 必填校验
- **WHEN** 用户提交缺少任一必填项的登记
- **THEN** 阻止提交并提示缺失字段

#### Scenario: 已登记用户不再强制填写
- **WHEN** 已提交过登记的用户再次登录
- **THEN** 不再要求重复填写登记表单

### Requirement: 证明材料上传

系统 MUST 支持上传证明材料文件（如营业执照、工牌、名片、账号截图）；MUST 限制允许的文件类型与大小并拒绝不合格文件；上传内容 MUST 仅对提交者与管理员可见。

#### Scenario: 上传合格文件
- **WHEN** 用户上传符合类型与大小限制的证明文件
- **THEN** 文件被安全保存并与该用户的登记关联

#### Scenario: 上传不合格文件
- **WHEN** 用户上传超出大小或类型不允许的文件
- **THEN** 拒绝并提示允许的类型与大小

### Requirement: 提交与审核状态流转

登记提交后 MUST 进入「待审核」状态；状态 MUST 为「待审核 / 已通过 / 已驳回」之一；被驳回时 MUST 记录并可展示驳回原因，用户 MUST 可修改后重新提交。

#### Scenario: 提交进入待审核
- **WHEN** 用户提交完整登记
- **THEN** 登记状态为待审核，且此时不得使用主应用

#### Scenario: 驳回后重新提交
- **WHEN** 登记被驳回且用户查看原因后重新提交
- **THEN** 登记回到待审核状态并保留历史

### Requirement: 基于审核状态的访问门禁

只有登记状态为「已通过」的用户 MUST 方可使用主应用数据功能；未提交登记 MAY 被引导到登记页，待审核用户 MUST 被引导到待审核提示页，被驳回用户 MUST 被引导到驳回页并可重新提交；上述门禁 MUST 同时在前端页面与后端接口生效。

#### Scenario: 待审核用户访问主应用
- **WHEN** 登记处于待审核状态的用户访问主应用页面或接口
- **THEN** 页面重定向到待审核提示，接口返回「未通过审核」错误码

#### Scenario: 审核通过后开放使用
- **WHEN** 用户登记被审核通过
- **THEN** 该用户可正常访问主应用数据功能

### Requirement: 管理员审核

系统 MUST 提供管理员审核能力：查看待审核/历史登记（含证明材料）、通过或驳回（驳回需填写原因）；管理员操作 MUST 经过管理员身份校验。

#### Scenario: 管理员通过登记
- **WHEN** 管理员对一条待审核登记执行通过
- **THEN** 该登记变为已通过，对应用户获得主应用访问权限

#### Scenario: 管理员驳回登记
- **WHEN** 管理员驳回一条登记并填写原因
- **THEN** 该登记变为已驳回并记录原因，用户可查看原因

#### Scenario: 非管理员操作审核
- **WHEN** 非管理员尝试调用审核接口
- **THEN** 返回无权限错误

### Requirement: 审核结果通知

系统 SHOULD 在审核状态变化时向用户提供结果通知；MVP MUST 至少提供应用内可感知的状态（登录/刷新或轮询可见），并 MUST 预留可插拔的通知通道以支持后续短信通知。「审核结果以短信通知」作为可选通道，未接入短信服务商时不得声称已发送短信。

#### Scenario: 审核结果应用内可见
- **WHEN** 用户登记状态发生变化后回到应用
- **THEN** 用户可看到最新的审核状态
