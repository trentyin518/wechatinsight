# Spec Delta

## Purpose

统一第三方微信公众号数据源接入方式，使业务逻辑只依赖标准化接口与数据契约，从而在供应商之间可替换、可比较、可限流，并保证数据来源与可信度可追溯。

## ADDED Requirements

### Requirement: 统一数据源接口

系统 MUST 定义一个统一的 `WeChatProvider` 接口，至少包含公众号搜索、账号资料获取、历史文章获取、文章互动指标获取四类操作；业务层与 API 层 MUST 只依赖该接口，不得直接调用任何供应商的 HTTP 接口或 SDK。

#### Scenario: 业务层通过接口获取数据
- **WHEN** API 需要一个公众号的历史文章
- **THEN** 系统通过当前配置的 `WeChatProvider` 实现获取数据，而不是直接请求供应商地址

#### Scenario: 更换供应商无需改动业务代码
- **WHEN** 平台把首选供应商替换为另一家已实现的适配器
- **THEN** 业务层、API 层与前端代码不需要修改

### Requirement: 标准化数据契约

每个供应商适配器 MUST 将原始响应转换为统一的账号、文章、指标结构，并保留 `provider` 标识；缺失字段 MUST 用 `null` 表示，禁止用 `0` 或空字符串替代未知值；所有时间 MUST 以带时区时间戳表示。

#### Scenario: 供应商未提供某指标
- **WHEN** 供应商响应中缺少在看数
- **THEN** 标准化指标里的 `wow_count` 为 `null`，而不是 `0`

#### Scenario: 时间字段带时区
- **WHEN** 适配器解析文章发布时间
- **THEN** 输出的 `published_at` 为带时区的时间戳

### Requirement: 账号与文章去重与供应商映射

系统 MUST 使用平台内部 ID 作为主键，并通过供应商映射表记录 `(provider, provider_account_id)` 到内部账号的对应关系；文章去重 MUST 基于规范化 URL 与供应商可靠标识，MUST NOT 仅凭标题判断重复。

#### Scenario: 同一供应商账号多次搜索命中
- **WHEN** 同一公众号通过同一供应商被重复搜索到
- **THEN** 系统复用已有内部账号 ID，并更新映射而不是新建账号

#### Scenario: 同一文章 URL 形式不同
- **WHEN** 两个来源返回指向同一文章的规范化 URL
- **THEN** 系统识别为同一文章，不重复入库

### Requirement: 调用约束与错误隔离

供应商适配器 MUST 执行超时控制、重试与限流，并 MUST NOT 将第三方原始错误、密钥或内部信息透传给调用方；调用失败 MUST 返回可识别的数据源不可用状态。

#### Scenario: 供应商超时
- **WHEN** 第三方 API 在超时时间内未返回
- **THEN** 适配器按配置重试，最终向上返回数据源不可用，而不是原始异常

#### Scenario: 供应商额度耗尽
- **WHEN** 第三方 API 返回额度耗尽
- **THEN** 系统记录该调用为失败并计入用量，且向前端返回明确的降级状态
