# Proposal

## Why

现有首页（`frontend/app/page.tsx`）只是一个极简的搜索框、分类 chips 与一段数据说明，缺少产品价值传达、能力概览与信任背书。作为平台的第一屏入口，它既没有讲清「平台能做什么」，也没有把「数据真实性优先」这一核心差异化可视化出来，导致用户理解成本高、转化弱。参考西瓜数据（data.xiguaji.com）首页成熟的信息架构，以「沿用其分区节奏、内容贴合真实数据语义」的方式重做首页，可在不放宽「null≠0、不伪造数字」约束的前提下显著提升可理解性与转化。

## What Changes

- 重做首页信息架构，借鉴西瓜数据首页的分区节奏，形成六段式结构：
  1. Hero 区：价值主张 + 主搜索入口 + 次级行动（如「按分类浏览」锚点）。
  2. 能力/价值卡片：数据真实性、统一数据源、指标溯源、历史快照等平台能力说明卡。
  3. 数据覆盖概览（对应西瓜数据的「数据大屏」）：展示**真实可获取**的聚合指标（如已收录公众号数、已收录文章数、接入数据源数、最近数据更新时间），全部来自本地库，缺失时显示「暂无」而非 0 或编造数字。
  4. 分类 / 已收录账号入口：按分类或热门账号提供跳转入口。
  5. 内容 / 更新区块（对应西瓜数据的资讯双栏）：展示最近更新或最新收录的内容，带采集时间标注。
  6. 底部数据说明：强化数据来源、覆盖范围与「缺失不等于 0」的说明。
- 新增首页可复用的展示组件（section 容器、能力卡、统计条、内容列表块等），沿用现有 `components/` 组织与全局 CSS 变量主题。
- 新增一个轻量只读覆盖统计端点（`GET /api/v1/overview`）为首页「数据覆盖概览」提供聚合数据；该端点只读本地库，不触发第三方调用，并在不可用时优雅降级。
- 强化数据真实性约束在首页的落地：所有数字来自真实数据，`null`/缺失显示「暂不可用」或「暂无」，每块数据标注来源与采集时间；任一数据区块失败时局部降级，不影响整页可用。

**不在本变更范围**：不实现排行榜、趋势图、账号对比、推广识别、用户系统与收藏等后续能力；不改变搜索/详情页面的既有行为；不接入新的第三方数据源。

### Modified Capabilities

- `web-app`: 首页 Requirement 由「提供搜索入口与数据说明」升级为「分区式产品首页」——新增能力卡片、真实数据覆盖概览、分类/账号入口与内容更新区块，并强化数据真实性（真实数字、缺失态、来源标注、局部降级）的要求。
- `query-api`: 新增只读覆盖统计端点 `GET /api/v1/overview` 的契约要求（聚合计数 + 最近更新时间 + 统一错误/降级行为），不触发第三方调用。

## Impact

- **前端**：重写 `frontend/app/page.tsx`；新增首页可视化组件（`frontend/components/` 下，如概览卡、能力卡、统计条、内容块）；扩展 `frontend/app/globals.css` 主题样式；`frontend/lib/api.ts` 与 `frontend/lib/types.ts` 增加 overview 数据类型与调用。
- **后端**：新增只读 `GET /api/v1/overview` 端点（聚合查询 `wechat_accounts` / `wechat_articles` / `data_providers` 计数与最近更新时间），复用统一分页无关的响应模型与错误信封；不调用第三方、不产生费用。
- **API/契约**：新增 overview 端点；既有搜索/详情接口契约不变。
- **数据真实性**：overview 聚合值均为真实计数；无数据时返回 0 或 `null`（`last_updated_at` 为 `null` 表示尚无数据），前端按缺失语义展示，绝不编造覆盖数字。
- **无新增第三方依赖、无数据库结构变更**（仅只读聚合）。
