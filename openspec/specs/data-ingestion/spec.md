# data-ingestion Specification

## Purpose

提供独立于用户请求的后台数据采集能力，通过可配置的同步任务与调度策略持续积累公众号、文章和指标快照，并记录每次第三方调用的用量与预估成本，以支撑成本可控的分层更新。

## Requirements

### Requirement: 三类同步任务

系统 MUST 提供三类采集任务：公众号资料更新、历史文章同步、文章指标更新；每个任务 MUST 记录类型、目标（账号或文章）、数据源、创建/开始/结束时间、状态、重试次数、错误代码、API 调用次数与预估成本。

#### Scenario: 同步历史文章
- **WHEN** 调度触发某账号的历史文章同步
- **THEN** 系统按分页游标拉取文章并幂等写入，记录任务与调用用量

#### Scenario: 更新文章指标
- **WHEN** 调度触发文章指标更新
- **THEN** 系统为该文章追加新的指标快照

### Requirement: 任务状态机

任务状态 MUST 支持 `PENDING`、`RUNNING`、`SUCCESS`、`RETRY`、`FAILED`；失败任务 MUST 可按重试策略转回 `RUNNING`，超过阈值后 MUST 转为 `FAILED`。

#### Scenario: 任务失败后重试
- **WHEN** 一次采集因临时错误失败且未超重试上限
- **THEN** 任务转为 `RETRY` 并在下次调度重试

#### Scenario: 超过重试上限
- **WHEN** 任务连续失败次数达到上限
- **THEN** 任务转为 `FAILED` 并保留错误代码

### Requirement: 幂等与游标续传

采集写入 MUST 幂等，重复执行同一任务 MUST NOT 产生重复的账号、文章或指标快照；长任务 MUST 保存分页游标并支持从断点继续，MUST NOT 无上限地一次同步全部历史文章。

#### Scenario: 重复执行同一任务
- **WHEN** 同一同步任务被重复触发
- **THEN** 系统不产生重复文章或重复快照

#### Scenario: 任务中途中断
- **WHEN** 长任务在部分分页后中断
- **THEN** 重新执行时从已保存游标继续，而不是从头重复拉取

### Requirement: 分层更新策略

系统 MUST 支持按数据价值分层调度（如用户监控账号与近期文章优先、普通活跃账号定期、长期不活跃与较早文章降低频率），并可依据配置的预算降低低优先级任务频率。

#### Scenario: 预算接近上限
- **WHEN** 当日调用费用接近配置上限
- **THEN** 系统降低低优先级任务的更新频率并记录该调整

#### Scenario: 热门账号优先
- **WHEN** 多个账号同时到期需要更新
- **THEN** 系统优先调度高优先级账号

### Requirement: 调用与成本记录

每一次第三方 API 调用 MUST 记录供应商、接口、请求时间、是否成功、返回条数、请求单位、预估成本、币种与关联任务 ID，并可据此汇总每日/每月用量与预估费用。

#### Scenario: 记录一次指标查询调用
- **WHEN** Worker 调用一次指标接口
- **THEN** 系统写入一条包含成本与关联任务的用量记录

#### Scenario: 查询每日费用
- **WHEN** 管理员查看当日用量
- **THEN** 系统按供应商与接口汇总调用次数与预估成本
